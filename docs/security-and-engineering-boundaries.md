# Security and engineering boundaries

The project root is explicit and separate from the Skill installation. Project IDs and relative artifact paths reject traversal, drive escape, case-insensitive collisions, overlapping parent/child writer scopes, and unauthorized output ownership. Work Packets grant exact file scopes. Independent reviewers have read-only access to engineering artifacts.

The requirements baseline and Manifest are versioned. CAD controls geometry; Blender is downstream. Canonical Mesh, exact_mesh measurements, independent read-back, stage evidence, Manifest ancestry, render QA, and non-circular hash ledgers remain mandatory for formal deliveries. `delivery/accepted/rN` is append-only; `working/` is editable and outside old delivery hashes. A Windows read-only attribute is only a warning; SHA-256 validates integrity.

The environment detector locates applications and queries versions. It cannot verify an application's export capability or attest to a model. Missing capabilities produce blockers. No tool detection grants permission to install software, alter Codex global configuration, or modify a real project.

The Skill does not provide fabrication readiness, statutory compliance, professional engineering approval, simulation validation, or a substitute for a licensed reviewer. Remove personal/proprietary information before any external issue report or repository publication. The Skill is licensed under MIT; external applications retain their own licenses.
