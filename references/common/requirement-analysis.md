# Requirement analysis

Create a traceable analysis before any modeling. Identify the user outcome, physical scope, target level (`concept`, `coordinated`, or `fabrication_support`), primary domain, source files, deliverables, exclusions, units, origin/axes, tolerances, controlled dimensions, interfaces, and acceptance evidence.

Classify every key value with `source`, `status`, `confidence`, `reason`, and `blocks`. Preserve the raw request verbatim in the baseline. Group clarification questions by blocking impact and ask only questions whose answers change geometry, coordination, safety, or delivery. An assumption is explicit, reversible, and never substitutes for a blocked critical fact.

Route only requests that have engineering dimensions/constraints, use CAD as authoritative geometry, require Blender downstream, and need cross-software consistency. Otherwise explain the boundary and use a narrower workflow.
